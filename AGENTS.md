# Project policy for agents

- Work only on an approved ticket with a clear acceptance condition; do not create an automatic micro-slice treadmill.
- Preserve the clean-room policy: use independent observations and project-owned notes, fixtures, tests, and code. Never copy legacy source, assets, schemas, or quest logic.
- Keep changes focused. Do not alter another lane's worktree, branch, automation, or unrelated files.
- Add or update focused tests for behaviour changes and run the relevant checks. Real-client claims require recorded QA evidence.
- Request independent review before integration; passing automation is evidence, not proof of complete parity.
- Keep documentation concise: update the short roadmap or smoke template when direction or QA changes, and put deep detail in the existing technical documents.
